# CheckAI: актуальные решения и состояние проекта

Обновлено: 19 ноября 2026 года. Документ описывает реализацию в этом репозитории, а не неподтверждённую конфигурацию VPS. Это справка о текущем устройстве проекта; следующие задачи определяются запросами пользователя.

## 1. Назначение и размещение

CheckAI собирает обращения распознанных ИИ-ботов к сайтам из access-логов Nginx/Apache2 в формате `combined` и показывает отчёты, рейтинг и журнал событий. Приложение написано на PHP 8.3, данные хранятся в SQLite.

- Корнем публичного веб-сайта должен быть каталог `public`. Исходный код, команды, схема базы и каталог данных должны оставаться вне веб-доступа.
- В репозитории есть Docker Compose: Apache/PHP обслуживает панель на `127.0.0.1:555`, отдельный сервис запускает сборщик. Docker — вариант запуска, а не источник настроек продукта.
- Проект можно запускать без Docker на сервере с PHP 8.3, PDO SQLite и Apache или Nginx. Для такого запуска веб-сервер должен направлять запросы в `public`, а сборщик — запускаться планировщиком ОС.
- SQLite находится в `var/checkai.sqlite3`; в Compose каталог `database` подключён к `/opt/checkai/var`, поэтому локальная база — `database/checkai.sqlite3`.
- Каждая установка хранит собственные настройки в своей SQLite. Значение `log_root` в приложении берётся из базы. Переменная Compose `CHECKAI_LOG_DIR` задаёт только исходную папку bind mount на хосте и не заменяет настройку базы.

## 2. Логи и сборщик

В таблице `settings` хранится `log_root`. Для новой базы значение по умолчанию — `/var/logs`; администратор может изменить его в разделе «Настройки». У каждого сайта в `sites.log_path` задаётся имя файла или относительный путь внутри корня. Абсолютные пути и обход корня через `..` отклоняются.

- При прямом запуске PHP корень логов задаётся абсолютным путём, видимым самому PHP-процессу, например `/path/to/logs`.
- На Linux пользователю PHP нужны право прохода (`x`) по каталогам пути и право чтения (`r`) у файлов логов. Например, при каталоге `root:main` с правами `2750` и PHP от `www-data` файл может отображаться в файловом менеджере, но оставаться недоступным приложению. Для закрытого каталога используйте точечный ACL, например `setfacl -m u:www-data:--x /var/logs-nginx`; чтение отдельных файлов при необходимости разрешайте отдельно. Не ослабляйте права каталога для всех пользователей.
- В Compose локальный каталог `../logs-nginx` подключается только для чтения как `/var/logs-nginx`. В базе контейнерной установки должен быть путь `/var/logs-nginx`, а не путь Windows-хоста.
- Добавление сайта требует, чтобы заданный файл уже существовал внутри `log_root`. Для диагностики проверяйте его от имени пользователя веб-сервера, например `runuser -u www-data -- test -r /var/logs-nginx/yoursite.com.access.log`, и проверяйте права по цепочке через `namei -l`.
- Сборщик читает access-логи Nginx/Apache2 в формате `combined` для включённых сайтов. В SQLite сохраняются только строки, чей User-Agent совпал с активной сигнатурой. Сравнение без учёта регистра; если совпало несколько сигнатур, первой проверяется наиболее длинная.
- Событие содержит сайт, бота, время из лога в UTC, HTTP-метод, путь без query string, статус и IP-адрес источника.
- Сбор можно запустить кнопкой «Обновить данные». В Compose отдельный сервис проверяет настройку автосбора и запускает `php bin/collect.php --checksettings` каждые пять минут. При запуске без Docker эту команду нужно добавить в cron или планировщик ОС.
- Файл читается с сохранённого byte offset. Курсор привязан к сайту и идентификаторам `device`/`inode`; неполная строка остаётся до следующего запуска. Запись событий и обновление курсора проходят в одной транзакции. Блокировка не допускает параллельный сбор.
- При новом inode текущего файла чтение начинается с нуля. Сборщик не ищет переименованные ротацией файлы и не обрабатывает сжатые архивы; дочитывание старого файла после ротации не гарантируется.

## 3. Схема данных

Схема создаётся и обновляется командой `php bin/init-db.php`. Текущая версия схемы — 20. Основные таблицы:

| Таблица | Назначение |
| --- | --- |
| `settings` | Корень логов, часовой пояс отчётов и переключатель автосбора. |
| `sites` | Домен, относительный путь к логу, включённость, примечание и архивный статус. |
| `companies` | Производители/организации ботов. |
| `bot_types` | Назначения ботов: обучение, поиск, запросы пользователей и прочее. |
| `bots` | Бот с компанией, видом, описанием, веб-сайтом, примечанием и состоянием. |
| `bot_signatures` | Активные и отключённые строки User-Agent. |
| `bot_ip_ranges` | Диапазоны IP, используемые для проверки источника бота. |
| `requests` | Распознанные события, включая путь, статус и IP. |
| `log_cursors` | Позиции чтения файлов логов. |
| `users` | Учётные записи и JSON-настройки отчётов конкретного пользователя. |

SQLite работает с WAL и внешними ключами. Для запросов используются индексы по времени, сайту, боту и виду бота. Отдельных агрегированных таблиц в текущей реализации нет: сводки строятся по `requests`.

## 4. Каталог и классификация ботов

Начальные справочники хранятся в `database/catalog.php`, `database/bot-types.php`, `database/bot-signatures.php` и `database/bot-details.json`. Каталог содержит OpenAI, Anthropic, Perplexity, DeepSeek, Google, Amazon, ByteDance и Common Crawl. IP-списки Amazon публикуются в JSON на официальных страницах; обновление выполняется из карточки каждого бота. Администратор может управлять компаниями, ботами, сигнатурами и назначением бота через панель.

Проверка сигнатуры User-Agent сама по себе не удостоверяет источник запроса. Для проверки IP используются диапазоны в `bot_ip_ranges`; в журнале доступна отметка результата. `bin/backfill-ips.php` — отдельная CLI-команда для восстановления IP в подходящих старых событиях по доступным логам.

## 5. Отчёты и пользовательские настройки

- «Отчёты» показывают сайты, компании, ботов, страницы и журнал запросов.
- «Рейтинг» раскрывает компании, ботов, сайты и страницы; переход со страницы ведёт к журналу её запросов.
- Общие фильтры включают период, вид бота, подтверждение IP, только страницы сайта и только HTTP 200.
- Время событий хранится в UTC. Часовой пояс группировки задаётся в `settings.report_timezone`; значение новой базы — `Asia/Yekaterinburg`.
- Период и фильтры пользователя сохраняются в `users.report_filters`. При переходах между отчётами и рейтингом выбранные даты передаются дальше.
- В списке сайтов сортировка доступна по названию (А–Я/Я–А) и числу запросов (по убыванию/возрастанию). По умолчанию — название по возрастанию; выбор хранится в настройках пользователя.

## 6. Учётные записи и доступ

Роли — `admin` и `user`. Администратор управляет сайтами, каталогом ботов и пользователями; пользователь просматривает данные и управляет собственным паролем. Пароли сохраняются как хеши PHP `password_hash()`. Формы защищены CSRF-токеном; ошибки доступа и входа не показывают данные БД.

Первую базу создаёт `php bin/init-db.php`, первого администратора — интерактивная команда `php bin/admin-setup.php`. В Compose для неё предусмотрен сервис `admin-setup`.

## 7. Известные ограничения и открытые решения

- Автоматического удаления старых событий и срока хранения в коде нет. Записи `requests` накапливаются, пока базу не очистят вручную. Требование о хранении 30 дней из старой версии описания не отражает фактическое поведение.
- Нет агрегатных таблиц; отчётные сводки выполняются запросами к журналу событий.
- После ротации переименованный файл не дочитывается автоматически; gzip и архивы не обрабатываются. Требуется отдельное решение по восстановлению после длительного простоя.
- При первом чтении текущий файл обрабатывается с начала. Период первоначального чтения отдельно не ограничен.
- Резервное копирование SQLite с WAL требует согласованного способа, учитывающего WAL; копирования только `checkai.sqlite3` во время записи недостаточно.
- Репозиторий не настраивает внешний Nginx/Apache2, TLS, DNS, firewall или VPS. Наличие локального Compose не подтверждает конфигурацию удалённого сервера.
- Нативная Windows-установка приложения целиком отдельно не проверялась. Поддержка Windows-пути в сборщике не означает, что серверная команда создания администратора и планировщик ОС уже проверены на Windows.
